### 1.1 The measurement gap (why beta7 passed while users still see clipped text)

Nothing in the local gate ever asks *"does this control's text fit its box at
125 % / 150 %?"*. `scripts/audit_layout.py` models authored rects at 96 DPI and
`tests/test_dialog_layout.cpp` feeds the solver **measured** heights, i.e. it
proves the solver works *given good measurements* — never that the runtime
measurements arrive at the right time. beta8 closes that hole in three
independent ways (§4).

### 1.2 A. The scroll mechanism makes content invisible **and unreachable** — BS-01 HIGH

`src/app/main.cpp:4207–4215` (`settingsScrollSetTab`):

```cpp
si.nMax  = std::max(0, m.rangeMax - 1);   // Win32 range is inclusive
si.nPage = static_cast<UINT>(m.pagePx);   // = 90 % of the viewport
```

`src/app/DialogLayout.hpp:530–536` (`ok::layout::scrollMetrics`):

```cpp
m.rangeMax = std::max(0, scrollRangePx);
m.pagePx   = std::max(1, viewportHeightPx * 9 / 10);
```

Win32 disables the scrollbar when `nPage >= nMax + 1`. With a viewport of
≈ 420–470 px, `nPage ≈ 400`; a one-wrapped-line overflow is `nMax ≈ 17`.
**`400 >= 18` ⇒ the scrollbar is disabled exactly when it is needed.** The page
children below the viewport have already been hidden by
`applySettingsScrollOffset()` (`main.cpp:4182–4185`: empty `SetWindowRgn`), so
the text exists, is not drawn, and has no UI affordance to bring it back.

*Triggers at 100 % DPI* — any single label that wraps one extra line (e.g.
`IDC_STAT_OUT_NOTE` at `main.cpp:4733`) is enough. The combo drop-down area of
a control that crosses the viewport edge is region-clipped the same way, which
is the "không kéo được danh sách" half of the report.

### 1.3 B. The layout is solved once, but many labels change text at runtime — BS-02 HIGH

`solveSettingsLayout()` runs only at `WM_CREATE` and `WM_DPICHANGED`
(`main.cpp:5234`). These controls are re-texted **later** and then clip until
the dialog is reopened:

| Control | Created | Written | Longest known content |
|---|---|---|---|
| `IDC_STAT_INFO_STATUS` | `main.cpp:4905` | `main.cpp:5297` (timer) | conflict-scan sentence, +2–3 lines |
| `IDC_STAT_LIVE_GATE` | `main.cpp:5103` | `main.cpp:5366` (timer) | "…không tác dụng vì: …" > 490 px at 100 % |
| `IDC_STAT_AI_STATS` | `main.cpp:5117` | `main.cpp:5455` (timer) | opt-in stats line, 2–3 lines |
| `IDC_STAT_COACH_ADVICE` | `main.cpp:5120` | `main.cpp:5461` (timer) | `[Thực tế]: …\n[Gợi ý]: …`, 3–4 lines |
| `IDC_STAT_APPV` | `main.cpp:4858` | `main.cpp:5352` (timer) | `exe — TẮT: loại trừ tự động (IDE/game)` in 210 px |
| `IDC_STAT_DIAG_RESULT` | `main.cpp:4892` | `main.cpp:5604/5619/5634/5643/5670` | `Đã xuất báo cáo: C:\Users\…\diag-report-….txt` |

### 1.4 C. The Chẩn đoán tab cannot *read* its own report — DS-01 HIGH

`ok::diag::report(40)` (emit-chain, process-resolution, display-metrics, all
counters — the beta7 truth release made it long) is reachable only through
`IDC_BTN_DIAG_REPORT` (file) and `IDC_BTN_DIAG_COPY` (clipboard)
(`main.cpp:5631–5680`). In-app, the user sees at most one clipped status line
(`IDC_STAT_DIAG_RESULT`, `main.cpp:4892`). A diagnostics tab that cannot display
its own report is the #1 support round-trip generator.

### 1.5 D. Other concrete layout defects found in source

* **BS-04 MED** — Tab Arcade: `IDC_STAT_STEERING` (`main.cpp:5019–5021`,
  y = `S(430)`) and `IDC_CMB_STEERING` (`main.cpp:5022–5024`, y = `S(428)`,
  bottom ≈ 448) sit **below the bottom edge of `IDC_GRP_ARCADE`**
  (`main.cpp:4947`, top `S(100)` + height `S(324)` ⇒ bottom = 424). The group
  stretch in `ok::layout::autoFit` only stretches for *contained* children, so
  the gap persists and grows with DPI.
* **BS-05 MED** — Combo boxes are created with their **drop-down height** as the
  window height: `main.cpp:4691` (`S(…)`, 200 px), `:4740` (160), `:4975` (120),
  `:5002`, `:5022` (140), `:5068`, `:5077`. The created window therefore extends
  far below the visible box (the code-table combo at `(128,186,210,200)` reaches
  y = 386, over the checkbox column; the fail-mode combo at `(280,344,220,120)`
  reaches over the BPM edit). Today only creation order (later siblings on top)
  keeps the *visible* controls clickable. `scripts/audit_layout.py:434–449`
  (`_geometry_rect`) deliberately models only the 25 px closed height, so the
  invisible windows are invisible to the gate — one future reorder becomes a
  "can't click / can't drag" bug. Under BS-01 the region-clipping hits exactly
  those invisible areas and breaks the drop-down.
* **BS-06 MED** — `ChaosLabWindow.cpp`: `WM_DPICHANGED` (`:579–585`) calls
  `applyLabFont()` (font only) and adopts the suggested rect; **no child rect is
  rescaled** — there is no `S()` idiom in that file (grep: only
  `MulDiv(13, …, 96)` for the font height at `:418`). At 125/150 % the text
  grows inside unchanged boxes ⇒ clipped/overlapping labels, including the
  "Mẹo: …" note and the 78 px "Gõ từng nhịp" checkbox.
* **BS-07 LOW** — `ArcadeWindow.cpp drawChrome()` footer hint is drawn with
  `TextOutW` and no measurement (`:1033` call site, FPS counter at
  `width - 76`): a long hint (B5 "Sai — nhấn Backspace N lần để sửa") can run
  under the FPS counter.
* **BS-08 LOW** — Tab Bàn phím `IDC_STAT_OUT_NOTE` (`main.cpp:4733–4736`,
  ~145-char string in a 34 px box ⇒ 3 lines at 96 DPI) is the main driver of
  tab-0 overflow. It *is* growable (the solver handles it); it must be pinned at
  100/125/150 so a future string edit cannot regress it.

### 1.6 E. v1.3.0 feature gap — FT-01 HIGH, VERIFIED in source

```
$ grep -rn "ProgressionEngine::instance()\|saveToFile\|loadFromFile\|serializeProfile\|deserializeProfile" src/app/
(no matches — the only hits are in src/core/*.{hpp,cpp} and tests/*)
```

* `ProgressionEngine::saveToFile()/loadFromFile()` — `src/core/Progression.hpp:186–187`

Consequence: **all XP, levels, achievements and the learned AI profile are lost

## 2. Beta8 goals & definition of done

**Goal.** Ship v1.3.0-beta8 (file build 1.3.0.9) in which:

1. Every piece of text the app can display is **fully visible and reachable**
   (no clipped line, no hidden row, no dead scrollbar) at 100/125/150 %, in all
   9 settings tabs, the Arcade Hub and the Chaos Lab.
2. Every control is **operable** — clickable, focusable, drag-able (sliders,
   scrollbars, combo drop-downs) — with no invisible window stealing input.
3. The **Chẩn đoán tab can show, copy, export and open its own report**.
4. The v1.3.0 features users depend on work end-to-end: **Chaos Lab incl.
   "gõ thật ra app" (Flexing) with honest feedback, Live Effects into external
   apps with an always-truthful gate readout, Arcade 8 games, Web hub parity,
   and Progression/AI that actually survive a restart**.
5. Every fix is **reproduced before, verified after**, and pinned by a test or
   audit that fails against the pre-fix code (`[VERIFIED]` vs `[HYPOTHESIS]`).

**Definition of done (release gate).** §6.
