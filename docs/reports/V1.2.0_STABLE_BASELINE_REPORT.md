# KieeKey v1.2.0 Stable — FROZEN BASELINE REPORT

**Purpose:** the reference every later v1.2.0 Stable change is measured
against. FROZEN before any stability work started, so that a regression
claim can be checked rather than asserted.

* **Baseline commit:** `d2453db` (branch `main`, pre-stability-work tree)
* **Baseline identity:** `KieeKey v1.2.0` (`kAppVersionFull = "1.2.0"`,
  `kTitle = "KieeKey v1.2.0"`, CMake `project(KieeKey VERSION 1.2.0)`)
* **Date frozen:** 2026-09-04
* **Host:** Linux x86-64 CI sandbox (the Windows product targets cannot be
  executed here — see *Scope limits* below)
* **Compiler:** `g++ (Debian 12.2.0-14+deb12u1) 12.2.0`, `-O2`
* **Windows cross-compiler:** `zig c++ -target x86_64-windows-gnu`

## 1. What was frozen

Three benchmark binaries were built from the **unmodified** `d2453db` tree
and kept untouched for the whole release:

| Binary | Source | What it measures |
|---|---|---|
| `/tmp/baseline/bin/perf` | `imebench_kit/harness/bench_perf.cpp` | Engine decision + encode latency, 4 workloads × 2 tiers, 2M keys × 3 interleaved runs, with a T0 no-op timing control |
| `/tmp/baseline/bin/e2e` | `tests/e2e_bench.cpp` (shim build) | Full producer→ring→consumer→barrier pipeline latency and throughput |
| `/tmp/baseline/bin/tone` | `tests/bench_tone_latency.cpp` | Per-tone-population end-to-end latency across the inline / inline-deferred / TSF commit paths |

Plus the whole existing test suite, run and recorded **before** any change:

| Suite | Baseline result |
|---|---|
| `tests/run_all_tests.sh` (13 harnesses) | ALL PASSED |
| `ctest` (3 registered targets) | 3/3 passed |
| `tools/crossbuild_windows.sh --check` | COMPILE CHECK PASSED (6/6 TUs) |
| `build/windows-x86_64/KieeKeyApp.exe` | 1,251,328 bytes, PE version `1.2.0.0`, manifest `1.2.0.0` |

The **audit gap that the baseline immediately exposed**: only 3 of the ~15
test programs in `tests/` were CTest targets. Twelve harnesses — including
the stress, soak, differential and hotfix suites — existed but were never
executed by any automated gate. A test that never runs cannot protect a
release, so "full test suite green" was true only in the weak sense of
"everything that ran, passed". This is recorded as baseline finding **B-0**.

## 3. Scope limits of this baseline (read before comparing)

1. **The Windows product cannot be executed on this host.** `KieeKeyApp.exe`
   and the TSF composer are cross-*compiled* only; every runtime number above
   comes from the portable shim (`OK_WRAP_NO_WIN32`), which reproduces the
   Win32 wrapper's ring, barrier and counter semantics in plain `std`. The
   Win32 `SetEvent`/`WaitForSingleObject` calls themselves are replaced by a
   condvar — so the numbers measure *the pipeline's structure*, not the Win32
   syscall cost.
2. **Host noise dominates the micro-benchmarks.** Repeated identical runs on
   this shared host vary by up to **±60 %** on p99 (see the release report,
   §"Methodology correction"). Any conclusion drawn from a single run of a
   frozen binary against a single run of a new binary is invalid. The release
   report therefore reports a **same-tree A/B** (rebuild the current tree with
   and without each change) as the authoritative latency comparison, and uses
   the frozen binaries only as a sanity anchor.
3. **No interactive Windows session.** Real-world UX items (tray icon
   lifecycle, DPI change with a real display switch, lock/unlock, UAC
   elevation) were audited by code inspection and by the new portable
   lifecycle test, not by running the app.

## 4. Baseline findings carried into the audit

| ID | Finding | Severity |
|---|---|---|
| **B-0** | 12 of ~15 test harnesses are not registered with CTest and run only by hand | P1 (process) |
| **B-1** | No version-consistency check exists; version strings are edited ad-hoc per release | P2 |
| **B-2** | No reproducible Windows cross-build script; the exe is produced by an ad-hoc cmake invocation | P2 |
| **B-3** | The pending-edit counter lives inline in `src/app/main.cpp` and is untestable off-Windows | P1 (blocks fixing the real bugs) |
| **B-4** | No state-transition matrix test for the engine's resync surfaces | P1 |

Everything in the release report is measured against the numbers in §2.
