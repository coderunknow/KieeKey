## 1. Method

### 1.1 Frozen baseline first

Before any candidate existed, on this host:

* g++ `(Debian 12.2.0-14+deb12u1) 12.2.0`, `-std=c++20 -O2`
* Linux 6.1 x86_64, Intel Xeon @ 2.60 GHz, **2 logical CPUs**, ~4 GB RAM
* Driver: `docs/bench/rc1-122/tput_driver.cpp` (clock-free 20 M-key prose +
  backspace storm, `mode=1` = `process` + `replacementUtf16`)
* Uninstrumented 3-run: **54.61 / 54.41 / 54.24 ns/key**, median **54.41**,
  sink `5436924`
* gprof (`-O2 -pg`) of the same driver: `handleMainKey` #1 at 13.55 ns/call
  (25.9 % self), `checkSpelling` 10.94 ns/call (24.7 %), `process` 4.50 ns/call

The 40.2 ns/key figure in the v1.2.1 RC3 report is **g++ 14.2 on a different
run**. It is not this host's v1.2.1 Stable number. Comparisons in this
document are always same-host, same-flags, same-driver.

### 1.2 Fair A/B

`git show HEAD:src/core/TextEngine.{hpp,cpp}` rebuilt as `build/bench-orig/tput`
with identical `g++ -std=c++20 -O2 -I src/core tput_driver.cpp TextEngine.cpp`.
Candidate rebuilt the same way. Runs interleaved. Sink must match.

### 1.3 What is / is not measurable here

Measurable: engine decision CPU/key, gprof self time, differential
correctness, the native suite. **Not** measurable: real `SendInput` / TSF /
registry latency, Windows startup, flicker, MSVC PE link. E2E shim p50 on
this 2-CPU host is a timer floor (~10 µs); engine is ~0.4 % of that floor.

## 3. Optimizations kept

All KEEP items are decision-identical by construction (see equivalence
comments in `TextEngine.cpp`) and were proven by the gate + lockstep
differential + identical sink.

### 3.1 Last-character sequence buckets in `handleMainKey` — KEEP

**Bottleneck:** after RC2's `quTail` / `tailMatches` pre-filter, gprof still
put `handleMainKey` at #1. Each of `kConsonantD` (79), `kVowelForMark` (79),
`kVowel` (≤32) still walked every sequence.

**Change:** constexpr buckets keyed by the last cell under `seqMask`
∈ {0, `kEndConsonantMask`}, visit order = original table (or flattened
group-then-seq) order. Analog of RC3's first-letter consonant buckets.

**Equivalence:** a sequence outside the bucket is exactly one whose
`tailMatches` was false — RC2 continued past it without calling
`checkCorrectVowel`. First winner is the same `i` / `(group, seq)`. Total
rejection still falls through to `insertKey`. `quTail` still short-circuits
the whole scan.

### 3.2 Bitmask classifiers — KEEP

* `isWordBreakChar`: two 64-bit masks replace the 32-way OR on every Char
  event (`process` first branch). ASCII-only; false above 0x7E. `[` / `]`
  stay **false** (they are Telex standalone keys, not word breaks).
* `isVowelChar`: one 32-bit test for `A E I O U Y` (used by
  `isConsonantAt` on the spelling / vowel-scan path).
* `isMarkKey` (Telex / Simple Telex): `S F R J X` as a bit test.

### 3.3 `checkSpelling` length-1 cheap exit — KEEP

A one-letter word cannot fire QU/GI specials, cannot run the vowel-combine
walk (`k-j` ≤ 1), and the end-consonant walk either accepts immediately
(single vowel) or is never reached (single unmatched consonant). Early
return with identical `tempDisableKey_` / `spellingOK_` / `spellingVowelOK_`.
`vowelStart_` / `vowelEnd_` are recomputed by `findAndCalculateVowel`
before any later consumer.

### 3.4 `vowelCombineFor` — KEEP

`kVowelCombine` is keyed A,E,I,O,U,Y (6 entries). Direct index replaces
the binary search on the `forceCheckVowel` path and on
`canHasEndConsonant` (37 453 calls / 20 M keys — not the bottleneck; done
for consistency).

### 3.5 Dual-emitter mutex — KEEP (not changed)

Inspected. The shipped Windows path has two emitters (TSF consumer +
inline SendInput fallback) that must not interleave `SendInput` streams.
Removing or shrinking `emitMtx` would be an engine-identity *and* a
correctness change. Profile does not put it on the Linux engine driver.
**No pipeline / hook / TSF / lifecycle change in this RC.**

## 7. E2E / Windows — honest boundary

* **E2E shim / tone / real-world typing benches were not re-run for this
  RC.** The engine change is 10 ns/key. On this host the shim p50 is ~10 µs
  (RC3 §7.3): the engine is not the term that moves that number.
* **Real SendInput / TSF / app flicker: NOT MEASURED** (Linux host, no
  Windows runtime).
* **MSVC x64 / ARM64 / ARM64EC PE build: NOT EXECUTED here.** The candidate
  is the same C++17 constexpr-table style that RC3 already compiled
  warning-clean; CI (`.github/workflows/build.yml`, windows-2022, `/W4 /WX`)
  is the PE gate. An in-class `static_assert` on a `static constexpr`
  member was **rejected** during this RC — GCC 12 (and MSVC) refuse it
  because the member's definition is not complete. That footgun is not in
  the tree.

## 8. Remaining bottlenecks

1. `handleMainKey` is still #1 (10 ns/call instrumented): the remaining
   cost is `checkCorrectVowel` + `insertKey`/`checkSpelling` of the winning
   path, not the scan.
2. `checkSpelling` 6 ns/call: vowel scan + tone-bit combine matching.
   Restructuring that walk is still risk ≫ gain (RC3 rejected it; still
   rejected).
3. User-visible Windows latency: hook wake + TSF commit + scheduler. The
   PerfProfile system (RC2) remains the shipped lever. This RC does not
   pretend otherwise.

## 10. Engineering assessment

v1.2.2 RC1 is a small, high-confidence engine pass: the profile's #1
function (`handleMainKey`) and the still-expensive `checkSpelling` are
attacked with the same compile-time bucket idea RC3 used on consonants,
plus three cheap classifiers. Output bytes did not change. The dual-emitter
mutex was left alone on purpose. The headline number on *this* host is
**54.41 → 43.85 ns/key (−19.4 %)**, which clears the host-scaled exceptional
bar; it is **not** a 40.2 → 38 claim, and it is **not** an E2E claim.
