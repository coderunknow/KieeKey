# KieeKey v1.2.2 RC4 — Performance Report

Campaign: **v1.2.2 RC4 Stable Qualification**. Baseline: frozen
**v1.2.2 RC3** (`dd3c42a`, tag `v1.2.2-RC3`). All measurements on the
captured host ([environment.txt](../bench/rc4-122/environment.txt)):
Debian 13, 2× Xeon, 4.1 GiB, containerized (governor UNKNOWN), g++ 14.2
`-O2` Release. Raw artifacts: [`docs/bench/rc4-122/`](../bench/rc4-122/).

**Headline:** the engine hot path is byte-identical between RC3 and RC4
(`git diff v1.2.2-RC3 HEAD -- src/core/TextEngine.* src/core/FlatTables.hpp
src/core/VietnameseTables* src/core/PerfProfile.hpp` is empty — VERIFIED).
Every measured delta is inside this host's noise band. Verdict:
**NO OPTIMIZATION REQUIRED — no regression.**

---

## 1. Methodology (unchanged from RC3 — no silent changes)

* Harness sources identical between the two sides (SHA-verified before the
  run: `tests/e2e_bench.cpp`, `tests/bench_tone_latency.cpp`,
  `tests/bench_tput_floor.cpp`).
* Same host, same compiler/flags, interleaved run order (RC3 then RC4 per
  repetition) to cancel host drift.
* RC3 built from a pristine `git worktree` at the tag — not from the
  modified tree.
* E2E workload: `ok_e2e_bench --keys=200000` (burst model, `model=all`),
  5 repetitions. Throughput floor: 20 000 000 keys, median of 3.
* The e2e harness itself documents the interpretation rules used below:
  RAW includes OS scheduler deschedules; the BURST/HOT (wake-free) and
  PIPELINE (deschedule-excluded) populations are the meaningful ones on a
  shared 2-core box.

## 2. Strict RC3 ↔ RC4 A/B (production-path E2E, 5 interleaved runs)

| Metric | RC3 (5 runs) | RC4 (5 runs) | median Δ |
|---|---|---|---|
| RAW p50 µs | 9.70–10.40 | 9.77–10.23 | +1.35 % (noise band) |
| **HOT p50 µs (protected)** | 9.39–9.87 (med 9.649) | 9.46–9.81 (med 9.664) | **+0.15 %** |
| HOT p99 µs | ~41–44 | ~41–46 | within noise |
| PIPELINE p99 µs | ~41–43 | ~42–45 | within noise |
| **throughput keys/s** | 14 104–14 435 (med 14 232) | 13 925–14 288 (med 14 227) | **−0.04 %** |
| peak RSS MB | 13.95–14.34 (med 14.09) | 13.99–14.31 (med 14.06) | −0.21 % |

Paired per-run deltas agree with the medians (e.g. hot p50 paired mean
+0.16 %). RAW p95/p99 spikes are scheduler deschedules (the harness counts
them explicitly: e.g. "8585 keys in 299 deschedule events"); they dominate
RAW tails on this shared host and are not engine metrics.

**Gate check (§15 policy):** no protected metric regresses >1 % beyond
noise → **PASS**.

## 5. CPU / memory / energy

* **CPU:** flat within noise (A/B tables above). No CPU-cost-affecting change
  shipped (engine identical; the only hot-adjacent change — relaxed atomics
  on `toggleKeyDown_` — executes only on Caps/Num/Scroll events).
* **Memory:** peak RSS flat (−0.21 %). No allocation-path change; the suite's
  zero-allocation steady-state checks pass on both builds.
* **Energy: UNKNOWN / NOT AVAILABLE** — no trustworthy telemetry exists on
  this host. CPU% is used only as a proxy above; **no battery-life claim of
  any kind is made.**

## 7. Competitor benchmark (independent methodology)

`tests/bench_three_engines.cpp`, vendored unmodified references, 2M keys × 5
runs ([competitor_three_engines.log](../bench/rc4-122/competitor_three_engines.log)):

| Engine | p50 ns/key | p90 | p99 | passages exact /15 |
|---|---|---|---|---|
| **KieeKey (RC4 tree)** | 112–121 | 187–211 | 401–445 | **15/15 ×5** |
| OpenKey 2.0.5 | 212–213 | 391–396 | 841–866 | 14/15 ×5 |
| UniKey 4.x UKEngine | 111 | 138–140 | 182–192 | 14/15 ×5 |

What is measured: engine-decision latency and composition correctness on
identical deterministic keystreams (real passages, tone-toggle stress,
backspace storms, fuzz). What is NOT measured: the shipped Windows typing
path (TSF/SendInput) — not reproducible headlessly; KieeKey's producer→
consumer architecture costs (hook hop, edit session) live outside this
harness and are covered by the E2E production-path model in §2. UniKey's
p50/p99 advantage on these streams is consistent with its simpler state
machine; the passage column reflects documented semantic differences
(KieeKey's spelling auto-restore keeps non-Vietnamese words raw where the
other engines' defaults mark them). No overall-superiority conclusion is
drawn from this narrow metric. Competitor defects found during the run are
documented in the log (UniKey 128-word buffer overflow; OpenKey 2.0.5
`checkForStandaloneChar` OOB read) — reported, not patched.
