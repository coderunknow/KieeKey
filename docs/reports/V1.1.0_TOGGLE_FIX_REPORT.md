# V1.1.0 — Toggle reliability fix report

Date: 2026-09-03
Scope: user report — "Whenever I open, it suddenly turn off for no reasons
and I don't know how to open it again."

## Verdict

Confirmed, with three real defect paths plus a feedback gap. The report
decomposed into:

1. **Phantom toggles** — the Ctrl+Shift chord state machine fired the
   global toggle in situations the user never pressed (reproduced).
2. **Persistence amplifier** — v1.1.0 persists the Vietnamese on/off state,
   so one accidental toggle became permanent across relaunches ("whenever
   I open, it is turned off").
3. **Zero feedback** — toggling was completely silent (icon color only),
   and the startup balloon claimed "ready" even when launching in the
   persisted OFF state, so the user could not discover the recovery.

## Defects reproduced (extreme test harness)

Harness: `tests/extreme_toggle.cpp` (portable; 9 scripted scenarios +
600k fuzzed event segments in 6 families with exact contract invariants).

| # | Scenario | Pre-fix |
|---|----------|---------|
| T2 | `Ctrl↓ S↓ Shift↓ Shift↑` (shortcut between modifier presses) | **TOGGLES (bug)** |
| — | `Shift↓ H↓ H↑ Ctrl↓ Ctrl↑ Shift↑` (capital + Ctrl tap) | **TOGGLES (bug)** |
| T5 | all-injected bare chord (RDP / remapper / automation) | **TOGGLES (bug)** |
| T6 | chord held across foreground change; resync re-seeds as clean | **TOGGLES (bug)** |
| T10 | 600k fuzz segments, 6 invariant families | 3 families violated |

The capital+Ctrl-tap path is the everyday repro of "typing normally and it
suddenly turns off".

### Root causes

* **P1 — contamination erasure hole.** `onKey` set `state = Dirty` on a
  non-modifier keydown, but the tail of the same call reset
  `!bothHeld → state = None` whenever the second modifier was not yet
  held. Any contamination during the single-modifier phase was forgotten;
  the chord then armed CLEAN on the second modifier press. The v1.1.0
  audit fixed only the both-held phase, not this hole.
* **P2 — injected chords.** The app fed every keyboard event (injected
  included) to the chord before any injected filtering. Third-party
  software that synthesizes bare Ctrl+Shift (RDP clients forwarding
  keystrokes, key remappers, automation tools) toggled the IME.
* **P3 — resync arming.** `resync(ctrl, shift)` set the chord CLEAN when
  the OS snapshot reported both held — a chord that started BEFORE the
  resync, whose bare-ness was never observed. Releasing it toggled.

## Fixes

1. `src/core/CtrlShiftChord.hpp` — state machine rewritten: contamination
   is CUMULATIVE and survives until the chord ends; the toggle fires at
   the first modifier release (historical behavior, pinned by
   `tests/test_hotfix.cpp` §2); `resync()` marks an unobserved chord Dirty
   instead of arming it. Fresh observed chords toggle exactly as before.
2. `src/app/main.cpp` (`onHookEvent`) — INJECTED MODIFIER events no longer
   drive the chord (KieeKey injects only VK_BACK / KEYEVENTF_UNICODE, so
   no real chord can be missed); injected non-modifier keydowns still
   cancel, so a remapped key between the modifiers remains "a key in
   between".
3. `src/app/main.cpp` — feedback: the hotkey toggle now shows a tray
   balloon ("Đã TẮT/BẬT … nhấn Ctrl+Shift để bật lại"); the startup
   balloon states the ACTUAL persisted state and teaches the recovery
   chord when launching OFF. The persisted on/off state itself is kept
   (OpenKey parity).
4. `src/core/ProcessMonitor.{hpp,cpp}` — portability fix found while
   building: `std::atomic<std::shared_ptr<const ForegroundInfo>>` (P0718)
   is not portable C++ (libc++/MSVC reject it; only GCC/libstdc++ accepted
   it). Replaced with a `std::shared_mutex`-guarded `shared_ptr` —
   concurrent readers, one writer per foreground change, identical
   observable semantics; the per-keystroke path never touches it.

## Verification

* `tests/extreme_toggle.cpp` — ALL PASSED on the fixed tree; the pristine
  pre-fix chord fails T2, T6 and 3 fuzz families.
* `tests/test_hotfix.cpp` — ALL HOTFIX TESTS PASSED (incl. §2 chord
  contract: bare chord toggles; Ctrl+Shift+S / arrows / Esc / Alt never
  toggle; cancelled chords recover).
* `tests/test_textengine.cpp` — ALL TEXTENGINE TESTS PASSED.

* imebench_kit: 4 correctness configs × 66,552 corpus words —
  byte-identical to pristine; 2M-key perf workloads — within the measured
  same-binary noise floor (engine is byte-identical).
* Windows x64 build (llvm-mingw clang 23, fully static — imports only
  system DLLs): PE validated, VERSIONINFO 1.1.0.0.

## Remaining known behavior (documented, by design)

The bare Ctrl+Shift chord is indistinguishable from the Windows
"between input languages" hotkey when the user configured Ctrl+Shift for
language switching: both fire. The toggle is no longer silent (balloon on
every toggle), so the state change is always visible and immediately
undoable. Changing the hotkey itself is a feature decision, not a defect
fix.
