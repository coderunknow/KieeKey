# KieeKey v1.1.3 — Quality/Performance Hardening Report

**Release:** v1.1.3 (from v1.1.2) · **Date:** 2026-09-03
**Scope mandate:** accuracy (P1), latency (P2), stability (P3), robustness in
real-world environments, regression protection, code quality. No new
features. No correctness traded for speed.

---

## 1. Method

1. **Full-pipeline audit** — LL hook producer (`ModernKeyHook`), transport
   (`win32_wrapper`, `LockFreeQueue`), engine (`TextEngine`), composer
   (`TsfComposer`), app layer (`main.cpp`), monitor (`ProcessMonitor`).
2. **Root-cause arbitration** — every engine↔oracle divergence class was
   replayed deterministically (new `--repro` mode) and arbitrated against
   the vendored upstream OpenKey 2.0.5 engine, not against opinion.
3. **Fix → test → re-verify** — each fix landed with a targeted regression
   test; the full differential suite was re-run at its complete budget.
4. **A/B benchmarks on the same host** — engine micro-bench and E2E burst
   latency, v1.1.2 vs v1.1.3 binaries.

---

## 2. Accuracy findings & fixes (P1)

### A1. CapsLock toggle tracker desynchronized by auto-repeat (critical, hook layer)

`applyModifierDelta` XORed the CapsLock/NumLock/ScrollLock bit on every
KeyDown. The LL hook receives auto-repeat KeyDowns while a key is held and
`KBDLLHOOKSTRUCT` carries no repeat flag: holding CapsLock for ~0.5 s XORed
the tracked bit 15–30×, leaving it out of phase with the OS. Every
subsequent tone-mark / đ / â transform re-emitted its word with the wrong
case ("vợ" → "vỢ") — the exact consumer-layer failure the v1.1.0 resync
mitigated after the fact.

**Fix:** edge-detect the up→down transition via a 256-bit
hook-thread-affine bitmap; the tracked level no longer moves on repeats.
The bitmap re-arms on `resyncModifiersFromOs`, and the RMW paths switched
from load+store to `fetch_or`/`fetch_and`/`fetch_xor` so a concurrent resync
cannot clobber a concurrent event update.

### A2. 36 engine↔oracle divergences (mega differential) — closed to 0

The shipped v1.1.2 state failed its own differential suite (36 text
mismatches; Cat C = 77). Minimized reproducers were replayed event-by-event
with a new tracing mode; three root-cause classes were identified, all
staleness in the *independent oracle* relative to the documented v1.1.0
engine contracts, arbitrated against upstream 2.0.5:

| Class | Example (repro) | Arbitration | Fix |
|---|---|---|---|
| VNI digit 6 with no O/A/E in the word composed onto a **stale `vowelEnd_`** from a previous word | `^uw<bs>6` → oracle swallowed the key with an empty replacement; engine + 2.0.5 type the literal digit | engine = 2.0.5 → oracle wrong | oracle mirrors `vniVowelEndValid_` (two scan sites + key mapping) |
| **Macro D3 model** — oracle kept the legacy raw-key buffer after a space-triggered expansion | `ok<space><bs>a3` → oracle "đượna3"-style (raw keys resurrected), engine "đượả" | engine = documented v1.1.0 D3 contract; user-correct | oracle spaceBranch/backspaceBranch/mainKeyBranch re-arm aligned (macroExpandLen_ mirror) |
| **Quick-consonant at the buffer limit** | 31-char word + quickStart/EndConsonant → `newCharCount` mismatch + stale 32nd char | engine bug (found by audit, confirmed by harness limits) | engine refuses the transform at `index_ ≥ kMaxBuff-1`; oracle mirrored; unit test added |

**Result:** 13 suites, ~268M events, full budget — **0 text mismatches,
0 stale-buffer defects, 0 over-backspace, 0 macro gaps, Cat C = 0**.

### A3. TSF commit into the previous application's document (critical)

`ensureContext()` trusted any non-null cached `ITfContext`. While the v3.5
hang-probe gate had TSF disabled, the consumer skipped focus re-resolution;
the first commit after the probe re-used the PREVIOUS app's document —
suppressed keystrokes, text injected into a backgrounded app. Same-window
focus changes (browser tabs, page ↔ omnibox) were also unobservable.

**Fix:** per-commit verification of the cached document against
`ITfThreadMgr::GetFocus` (an in-process msctf read, no marshaling — a few
ns per batch). Mismatch → re-resolve from the real focus; commit failure →
existing SendInput fallback.

### A4. Truncated context re-sync corrupted backspace accounting

The caret read-back (`Resync`) replays raw ASCII keystrokes. With composed
Vietnamese before the caret ("chào|"), the ASCII tail is just "o" —
replaying it seeded the engine with a 1-char word while 5 UTF-16 units were
visible; the next tone key then deleted the wrong characters. Strictly
worse than not resyncing.

**Fix:** the session fails when a non-ASCII letter (or digit) directly
precedes the ASCII run; the caller keeps the empty-buffer degradation
(`startNewSession`), which is always safe.

### A5. Toggling OFF could leave queued edits applying out of order

The disabled early-return produced no consumer wake and no drain; letters
typed in OFF mode reached the app immediately while a stale TSF edit
committed later and deleted the wrong characters. **Fix:** OFF now drains
the pending queue (bounded by the barrier budget) and an in-flight decision
re-checks the enabled flag under `engineMtx`.

## 3. Latency findings & fixes (P2)

### L1. Phantom pending-edit race — 1 ms stall per keystroke (critical)

Producer incremented `pendingEdits` AFTER the ring push (relaxed); the
consumer's "reached zero" notification compared against the fetch_sub
previous value. A preemption between push and increment left a phantom
pending count that never drained — every later pass-through keystroke then
paid the full 1 ms barrier wait (a ~100× latency multiplier on the entire
keyboard until a coincidental reset).

**Fix:** publish the count BEFORE the push (`acq_rel`, rollback on push
failure); the zero-test re-reads the counter after an acq_rel subtract.
Verified by the existing barrier race tests plus the differential harness.

### L2. Wheel events took the ordering barrier on the shared hook thread

A wheel notch does not move the caret, but the drain wait ran in the LL
mouse callback — scrolling while edits were in flight stalled keystrokes up
to the 1 ms budget per notch. **Fix:** buttons keep the barrier (caret
moves), wheel skips it.

### L3. Settings dialog held the engine lock across control reads

`settingsFromControls` kept `engineMtx` across ~25 `IsDlgButtonChecked` /
`SendMessageW` cross-thread control reads on every OK/Apply. **Fix:** all
reads hoisted above the lock (fail-safe fallbacks preserved); only the
state swap runs in the critical section.

### L4. Stale keyboard-layout cache on in-window layout switches

Win+Space / Ctrl+Shift within one window fires no foreground event; the
cached HKL decoded keys under the previous layout until the next app
switch. **Fix:** the foreground thread's HKL is re-read on Space/WordBreak
keystrokes — two user-mode reads, no syscall, no measurable cost.

## 4. Stability findings & fixes (P3)

### S1. Vietnamese keystrokes vanish in elevated applications (critical)

Both output paths fail silently under UIPI: TSF edit sessions cannot marshal
into an elevated target and `SendInput` is blocked with no error
indication. Typing "á" swallowed the letters outright (elevated cmd/
PowerShell/Task Manager/RegEdit). **Fix:** `ProcessMonitor` probes the
foreground's integrity level (`OpenProcessToken` + `TokenElevation`,
once per app switch); an elevated target joins the auto-exclusion set —
raw pass-through + engine reset — so keystrokes are never lost.

### S2. Watchdog could not detect a dead keyboard hook while the mouse moved

The fast path collapsed keyboard/mouse/self-inject stamps into one max;
Windows removes LL hooks individually, so a dead `WH_KEYBOARD_LL` stayed
invisible during mouse-only activity. **Fix:** the keyboard stamp is
evaluated independently; the ambiguous "system input fresh, keyboard stamp
stale" state is resolved by an ACTIVE PROBE — a self-tagged VK 0xFF
(unassigned) down+up that a live hook stamps and filters (the app never
sees it) and a dead one never stamps. Dead-hook detection now completes in
~10–25 ms even during mouse-only sessions. New regression test added.

### S3. `SendInput` failures silently dropped edits and masked the watchdog

The emitter stamped the self-heal tick BEFORE the call (feeding the
heartbeat with input that never reached the system) and ignored the result.
**Fix:** stamp only accepted input; rejections are counted
(`sendInputFailed()`); partial batches accounted exactly.

### S4. Cross-thread inline emission could interleave batches

Hook-thread ring-full fallback and consumer fallback could run `SendInput`
concurrently — atomic per call, not across calls. **Fix:** a function-local
mutex on the (cold) emit path; the hot single-caller inline path is
unaffected.

### S5. Lifecycle hardening (multiple small root-cause fixes)

* `ProcessMonitor::start()` refuses restart after a stuck-detach (two pumps
  fighting over one WinEvent hook).
* Stuck-detach pumps can no longer reach the watchdog callback after owner
  teardown (`pumpTick_` nulled).
* OOM at `noexcept` boundaries degrades instead of terminating: monitor
  snapshot keeps the previous state and retries; self-healing starts
  disabled; the consumer drain loop falls back to SendInput.
* Composer attach latch resets on failure (TSF retryable, not dead for the
  process lifetime); `RPC_E_CHANGED_MODE` fails attach cleanly.
* Mid-session TSF failures deliver only the unapplied suffix
  (`appliedCount`) — no more duplicated pure-insert deltas ("t"+"to" →
  "tto").
* `WM_ENDSESSION` quits cleanly (no live tray icon over a dead IME);
  `WM_CREATE` is exception-safe and publishes the handle only on success;
  `GetMessageW(-1)` no longer runs the full shutdown path.
* `DropOldest` overflow policy removed (producer-side `try_pop` violated
  the SPSC contract; the app never selected it).
