# KieeKey v1.1.0 — Benchmark & Verification Report

**Date:** 2026-09-02 · **Comparison:** v1.0.1 (baseline) vs v1.1.0 (this release)
**Environment:** Linux CI-class x86-64 host, GCC 14.2, `-std=c++23 -O2`, shared
machine (run-to-run scheduler noise is expected and is why every benchmark is
run multiple times / interleaved).

The native test path of this repository builds the platform-independent core
(TextEngine, ring, wrapper logic through `OK_WRAP_NO_WIN32` + the deterministic
Win32 shim) and the E2E/tone latency harnesses on any OS; the Win32-specific
targets (KieeKeyApp.exe, TSF composer against a real text store) are exercised
by CI on Windows. All results below were produced with the exact shipped
sources of each version, compiled from the same compiler with identical flags.

---

The v1.0.1 behavioral goldens are **byte-identical** in v1.1.0 — every engine
fix is either a bounds/lifetime fix (no visible change) or fires only on paths
that previously produced provably wrong state (resync replay, macro backspace,
VNI stale index, dead modern-orthography conditions which are subsumed by the
adjacent live conditions for all reachable words).

## 2. Engine micro-benchmark (`bench_engine`, ns/key, lower is better)

| Workload | v1.0.1 | v1.1.0 | Δ |
|---|---|---|---|
| `xin chao cac ban` (plain Telex words) | 100 | 100 | 0 % |
| `ban as aw aa ow uw uow` (tone/hat keys) | 92 (5-run: 91–93) | **91** (5-run: 90–91) | −1 % |
| `toi la nguoi viet nam` (mixed sentence) | 101 | 101 | 0 % |
| `a1 a2 … o7 u7` (VNI tone digits) | 62 | **59** | −5 % |

*(A single outlier run of 227 ns/key for the tone/hat workload was traced to
transient host contention — five consecutive re-runs of both binaries
interleaved show v1.1.0 at parity or slightly faster.)*

Context: a 200 WPM typist produces one key every ~58 ms. The engine decision
costs ~0.10 µs/key — 0.0002 % of the human-typing budget — and is unchanged.

## 3. E2E pipeline latency (`ok_e2e_bench --keys=100000`, 6 runs each,
interleaved A/B; µs, lower is better; "burst/hot" = the wake-free typing
population; PIPELINE = deschedule-excluded)

| Metric | v1.0.1 (6 runs) | v1.1.0 (6 runs) | Verdict |
|---|---|---|---|
| p50 | 8.96 – 9.71 (median 9.44) | 9.42 – 9.72 (median 9.56) | **parity** (Δ ≈ +1 %, within noise) |
| p99 | 39.0 – 47.3 (median 43.9, σ ≈ 3.1) | 47.0 – 52.8 (median 48.2, **σ ≈ 2.1**) | parity; v1.1.0 spread is **tighter** |
| p99.9 | 71.0 – 93.8 (median 81.3) | 75.1 – 85.2 (median 80.5) | **parity / slightly better** |
| max | 93.7 – 100.0 | 99.2 – 100.0 | parity (spin-cap bound) |
| throughput | 13 807 – 14 521 keys/s | 14 428 – 14 505 keys/s | parity |
| RSS (pipeline) | ~6.55–6.65 MB | ~6.55–6.58 MB | parity |

Reading: the entire v1.1.0 safety surface — bounds guards, replay-mode flag,
VNI validity flag, macro visibility model, QPC barrier deadline — costs
nothing measurable on the keystroke path. The p99 wobble between runs
(±4 µs) is the shared host's scheduler and is visible in the BASELINE itself
(the same binary varies by ±4 µs across runs); interleaved A/B runs confirm
the two versions sit inside each other's spread, with v1.1.0 showing the more
stable tail.

## 5. What the benchmarks CANNOT show here (Windows-only fixes)

The following v1.1.0 fixes are only observable on Windows with real
applications; they are verified by the new regression tests and code-level
invariants, and expected to show as *eliminated failure modes*, not as
throughput changes:

* TSF edit-session `Release()` (per-keystroke COM-object leak in
  browsers/Office — the Auto-TSF set).
* `textBeforeCaret` synchronous, session-owned read (no stack-use-after-return).
* Slow-commit watchdog (a starving foreground STA degrades to inline instead
  of wedging the consumer).
* Live CapsLock/NumLock/ScrollLock tracking; Ctrl+Shift chord re-seed on app
  switch; AltGr composition; dead-key flush; mouse-wheel word break.
* ExitProcess shutdown path when a worker had to be detached (no
  static-destruction race over a wedged thread).

## 6. Regression tests added in v1.1.0 (`tests/test_textengine.cpp`)

| # | Regression guarded |
|---|---|
| R1 | Standalone `w`/ư reversal at word start — bounds-safe, identical output |
| R2 | Context re-sync replays RAW (no stored transforms): `as` → `asd` → restore keeps `asd` (no ghost duplication); composed words (`chào`) correctly refuse replay |
| R3 | Macro expansion + backspace visibility model: `cn`+Space → `chào` (space consumed, D3); backspace walks the expansion down; composition resumes cleanly; no phantom raw-key restore; non-matching words unaffected |
| R4 | VNI digit 6 with no vowel in the current word passes through raw (`ng6`), while `a6`/`oa6` still compose (`â`/`oâ`) |

## 7. Verdict

v1.1.0 delivers the reliability/correctness/UX work at **zero measurable
performance cost**: engine decision time, E2E latency percentiles, throughput
and memory are at parity with v1.0.1, while five families of
wrong-output/ghost-state bugs, one OOB read, one COM leak, one
stack-use-after-return and one shutdown race are eliminated, and the macro
("Gõ tắt") feature is now real.
